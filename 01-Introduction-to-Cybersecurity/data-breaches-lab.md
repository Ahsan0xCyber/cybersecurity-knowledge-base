Data Breaches — Practical Lab

1. Lab Objective

To analyze data breaches and security incidents, identify exposed information and security weaknesses, and recommend appropriate prevention methods.

2. Security Breach Documentation

The following table documents selected security incidents and cybersecurity course scenarios.


| Incident Date | Organization / Target | Compromised Data | Security Weakness | Prevention |
|---|---|---|---|---|
| August 2020 | Razer | Customer information reportedly exposed | Cloud misconfiguration | Secure cloud settings and access controls |
| September 2017 | Equifax | Sensitive personal information | Unpatched web application vulnerability | Apply security patches and assess vulnerabilities |
| 2017 | Persirai Botnet | IP cameras compromised | Malware exploiting vulnerable cameras | Update firmware and change default credentials |
| To be verified | Hotel chain scenario | Guest names, emails, and phone numbers | Compromised employee credentials | Enforce MFA and monitor database access |
| To be verified | eLearning platform scenario | Student contact and enrollment information | Publicly accessible cloud database | Restrict public access and secure permissions |


Note: The hotel chain and eLearning platform incidents are scenarios from course material, not confirmed real-world incidents. The Razer incident details should be verified against reliable public reporting before being treated as definitive. Persirai is an IP camera compromise and botnet incident, rather than a conventional customer-data breach.

3. Incident Analysis

When investigating a security incident, identify the following:

- Affected Asset: The system, device, database, or network affected.
- Exposed Data: The information accessed, stolen, or disclosed.
- Attack Vector: The method used to gain unauthorized access.
- Security Weakness: The vulnerability, misconfiguration, or control failure that enabled the incident.
- Impact: The consequences for users or the organization.
- Prevention: The security controls that could reduce the likelihood or impact of a similar incident.

4. Lab Takeaways

- Identify what information or assets were exposed or compromised.
- Understand the difference between a vulnerability, an exploit, and an impact.
- Recognize common security weaknesses, including unpatched software, compromised credentials, and cloud misconfigurations.
- Recommend appropriate controls based on the underlying cause.
- Verify real-world incidents using reliable sources.
- Distinguish documented incidents from hypothetical course scenarios.

5. Key Security Principle

Identify → Investigate → Document → Prevent
